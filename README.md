# NEON STEP

Python + FastAPI로 실행하는 PC용 4레인 웹 리듬게임입니다. 같은 서버에서 화면, 음악, 채보, 기록 API를 제공합니다. 외부 음악이나 API 키 없이 50초 오리지널 데모를 바로 플레이할 수 있습니다.

## 설치와 실행

Python 3.11 이상을 권장합니다. 이 저장소의 실제 검증 환경은 Windows / Python 3.14입니다. JavaScript 테스트에는 Node.js 20 이상이 필요하며, 게임 실행 자체에는 Node.js가 필요하지 않습니다.

저장소 루트에서 Windows PowerShell로 실행하세요.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m rhythm_game
```

설치 후에는 마지막 명령 하나로 실행합니다. 가상환경 활성화나 별도 프런트엔드 서버는 필요하지 않습니다.

접속 주소: **http://127.0.0.1:8000**

첫 실행 시 음악과 SQLite 저장소를 자동 생성합니다. 종료하려면 서버 터미널에서 `Ctrl+C`를 누르세요.

포트가 사용 중이라면:

```powershell
.\.venv\Scripts\python.exe -m rhythm_game --port 8001
```

이때 접속 주소는 `http://127.0.0.1:8001`입니다. 오디오는 사용자 동작과 보안 컨텍스트가 필요하므로 로컬에서는 `localhost` 또는 `127.0.0.1`을 사용하세요. 향후 원격 공개에는 HTTPS를 구성해야 합니다. 이 프로젝트는 클라우드 배포나 리소스 생성을 수행하지 않습니다.

## 조작법

1. 곡과 설정을 선택하고 **게임 시작**을 누릅니다.
2. 3초 카운트다운 이후 음악이 재생됩니다.
3. 왼쪽부터 **D / F / J / K**를 노트가 판정선에 닿을 때 누릅니다.
4. 곡이 끝나면 결과가 표시되고 자동 저장됩니다.

| 동작 | 방법 |
|---|---|
| 노트 입력 | D / F / J / K, 물리 키 위치 기준 |
| 일시정지 / 재개 | Esc 또는 일시정지 / 재개 버튼 |
| 처음부터 플레이 | 다시 시작 |
| 플레이 종료 | 곡 선택 |
| 기록 재조회 | 기록 새로고침 |
| 저장 실패 재시도 | 결과 저장 재시도 |

키를 계속 누르는 자동 반복 입력은 판정하지 않습니다. 다른 레인의 동시 입력을 지원합니다. 탭이 숨겨지거나 창이 포커스를 잃거나 오디오가 중단되면 자동 일시정지하며, 돌아와도 자동 재개하지 않습니다.

## 화면과 시각 효과

- 프로젝트에서 직접 제작한 [SVG 앨범 아트](static/artwork.svg)를 사용합니다. 외부 이미지 요청이나 이미지 생성 서비스, 추가 라이브러리가 필요하지 않습니다.
- 네온 포털 커버, 반투명 HUD, 키 색상별 레인과 그라데이션 판정선으로 화면을 구성합니다.
- 내려오는 단타 노트에는 그라데이션, 하이라이트와 짧은 빛의 궤적을 적용합니다. 궤적은 장식이며 롱노트가 아닙니다.
- 실제 Perfect / Good 판정 때 해당 레인에 파동과 스파크가 표시됩니다. 동시 입력은 레인별로 표시하며, 빈 입력은 성공 효과를 만들지 않습니다. Miss는 별도의 색상으로 구분합니다.
- 3초 시작 카운트다운에 진행 링과 숫자 강조 효과를 표시합니다. 카운트다운 길이와 기존 판정 규칙은 변경하지 않습니다.
- 노트 이동과 히트 효과는 오디오 기준 시간을 사용합니다. 일시정지는 효과도 고정하고 재시작은 효과를 초기화합니다.
- 운영체제·브라우저의 **모션 감소** 설정을 존중해 궤적·파동·스파크와 장식 애니메이션을 생략합니다. 플레이에 필요한 노트 이동과 판정 색상은 유지합니다.
- 긴 설정·기록 설명은 펼쳐 보기로 제공하며 키보드 포커스와 오류 안내는 유지합니다.

## 설정

설정은 브라우저 `localStorage`의 `neon-step-settings`에 저장되어 새로고침 후에도 유지됩니다.

- **볼륨:** 0~100%. 플레이 중에도 변경 가능합니다.
- **노트 속도:** 250~850px/s. 화면 이동 속도만 바꾸며 음악과 판정 시각은 바꾸지 않습니다.
- **타이밍 오프셋:** -250~250ms 정수.
  - `+75ms`: 노트 도착과 입력 판정 목표를 원래 음악 시각보다 75ms 늦춥니다.
  - `-75ms`: 둘 다 75ms 앞당깁니다.
  - 예: 1,000ms 노트에 `+75ms`를 적용하면 1,075ms 입력이 Perfect의 중심입니다.

속도와 오프셋은 플레이 중 및 일시정지 상태에서 잠깁니다. 변경하려면 곡 선택으로 돌아가세요. 잘못된 저장 설정은 오류 안내 후 기본값으로 복구합니다. 브라우저가 저장소 접근을 막으면 설정 저장 실패를 안내합니다.

## 판정과 점수

| 판정 | 오프셋 보정 후 시간 오차 | 점수 |
|---|---|---|
| Perfect | 절댓값 ≤ 50ms | 1,000 |
| Good | 50ms < 절댓값 ≤ 100ms | 500 |
| Miss | 미판정 노트가 100ms 범위를 지남 | 0 |

- 같은 레인의 판정 가능한 노트 중 가장 가까운 노트를 선택합니다.
- 거리가 같으면 채보에 먼저 작성된 노트를 선택합니다.
- 각 노트는 한 번만 판정합니다. 빈 입력은 점수와 콤보에 영향을 주지 않습니다.
- Perfect / Good은 콤보를 증가시키고 Miss는 콤보를 초기화합니다.
- 정확도 = `(Perfect 수 + Good 수 × 0.5) / 전체 노트 수 × 100`, 소수점 두 자리 반올림.
- 플레이 도중 정확도도 전체 노트 수를 분모로 사용합니다.
- 음악 종료와 마지막 노트의 보정된 판정 범위가 모두 끝난 후 결과로 전환합니다.

## 동기화 구조

음악을 예약한 `AudioContext.currentTime`으로 게임 시간을 계산합니다. 입력과 노트 위치도 이 시간을 사용합니다. `requestAnimationFrame`은 화면을 갱신할 뿐 프레임 수나 타이머로 게임 시간을 누적하지 않습니다.

일시정지는 진행 위치를 고정하고 오디오 소스를 정지합니다. 재개하면 새 소스를 기존 위치에서 재생하므로 남은 카운트다운과 판정 상태도 유지됩니다. 재시작은 음악·노트·키 상태·점수를 초기화합니다.

이는 소프트웨어 시계 일치를 보장하는 구조이며, 스피커·헤드폰·디스플레이의 실제 출력 지연을 제거한다는 의미는 아닙니다. 필요하면 타이밍 오프셋으로 보정하세요.

## 저장소와 API

기본 생성 위치:

```text
data\
  audio\demo.wav
  records.sqlite3
```

`data`는 Git에서 제외됩니다. SQLite 테이블과 인덱스 초기화는 반복 실행해도 기존 기록을 보존합니다. 다른 저장 위치는 서버 시작 전에 지정할 수 있습니다.

```powershell
$env:RHYTHM_DATA_DIR = 'C:\Demo\rhythm-data'
.\.venv\Scripts\python.exe -m rhythm_game
```

기록에는 곡 ID, 점수, 최대 콤보, 판정별 수, 정확도, UTC 플레이 시각, 재시도 중복 방지용 무작위 플레이 ID를 저장합니다. 사용자 계정이나 개인 식별 정보는 수집하지 않습니다.

| API | 기능 |
|---|---|
| `GET /api/songs` | 곡 메타데이터와 노트 수 |
| `GET /api/songs/{id}/chart` | 채보 |
| `GET /api/songs/{id}/records` | 최고 기록 `best`와 최근 10개 `recent` |
| `POST /api/results` | 결과 검증 및 저장 |

API 문서: http://127.0.0.1:8000/docs

데모 곡을 모두 Perfect로 판정한 결과 요청 예시:

```json
{
  "attempt_id": "d663e048-0d85-4d02-8d1c-96330c891f08",
  "song_id": "demo",
  "perfect": 108,
  "good": 0,
  "miss": 0,
  "max_combo": 108
}
```

서버는 점수와 정확도를 직접 계산합니다. 클라이언트가 보낸 `score`, `accuracy` 등의 추가 필드는 거부합니다. 존재하지 않는 곡, 비정수·음수 값, 잘못된 UUID, 판정 합계 불일치, 불가능한 최대 콤보를 검증합니다.

동일한 플레이 ID와 동일한 결과의 재전송은 같은 기록을 반환하며 중복 저장하지 않습니다. 같은 ID로 다른 결과를 보내면 `409`입니다. 최고 기록은 점수 → 정확도 → 최대 콤보 → 최신 기록 순으로 선택합니다.

저장 실패 시 화면의 결과를 유지하고 재시도를 제공합니다. 결과가 저장됐지만 기록 목록 갱신에 실패한 경우에도 이를 구분해 안내합니다.

**주의:** 입력 이벤트나 실제 플레이 여부는 서버에서 검증하지 않습니다. 기록은 인증 없는 로컬·데모용이며, 공식 온라인 랭킹이나 부정행위 검증 점수가 아닙니다. 향후 인터넷 공개에는 인증, 요청 제한, 서버 측 플레이 검증 등을 별도로 설계해야 합니다.

## 데모 음악과 새 곡 추가

### 오리지널 데모

[음악 생성 코드](rhythm_game/demo.py)는 Python 표준 라이브러리 `math`, `random`, `array`, `wave`만 사용합니다. 고정 시드 `2026`, 120 BPM의 신시사이저 멜로디·킥·스네어·하이햇을 합성합니다.

- 길이: 정확히 50초
- 형식: 22,050Hz / 16비트 PCM / 모노 WAV
- 첫 노트: 3,500ms
- 마지막 노트: 46,000ms
- 채보: [demo.json](songs/demo.json), 108개 단타 노트 및 동시 입력
- 외부 샘플·음악·이미지를 사용하지 않습니다.
- 채보는 직접 작성한 고정 패턴이며 자동 채보 분석 기능이 아닙니다.

생성된 파일이 있으면 재사용합니다. 데모를 재생성하려면 서버를 종료한 후 해당 파일만 삭제하고 다시 실행하세요.

```powershell
Remove-Item .\data\audio\demo.wav
.\.venv\Scripts\python.exe -m rhythm_game
```

### 새 곡

1. 사용 권한이 있는 **PCM WAV** 파일을 `data\audio`에 넣습니다. 파일명은 영문·숫자·밑줄·하이픈만 사용합니다.
2. `songs`에 아래 형식의 JSON 파일을 추가합니다.
3. WAV의 실제 길이를 밀리초로 반올림해 `duration_ms`에 넣습니다. 오차 허용은 2ms입니다.
4. 음악에 맞는 `time_ms`를 직접 작성하고 시간순으로 정렬합니다.
5. 서버를 재시작합니다.

```json
{
  "id": "my-song",
  "title": "내 곡",
  "bpm": 120,
  "duration_ms": 50000,
  "audio_path": "/audio/my-song.wav",
  "notes": [
    {"lane": 0, "time_ms": 3500},
    {"lane": 1, "time_ms": 4000},
    {"lane": 2, "time_ms": 4000}
  ]
}
```

곡 ID는 영문 소문자·숫자·밑줄·하이픈, 레인은 `0~3`, 노트 시각은 0 이상의 정수입니다. 노트는 1~20,000개이며 같은 레인·시각의 중복 노트는 허용하지 않습니다. 마지막 노트 뒤 최소 100ms의 판정 여유가 필요합니다. BPM은 정보 표시용이며 실제 판정은 `time_ms`를 사용합니다.

잘못된 채보나 음악 파일은 조용히 건너뛰지 않습니다. 서버 시작을 중단하고 파일명과 오류를 터미널에 표시합니다.

- Python 테스트는 임시 저장소를 사용하므로 실제 플레이 기록을 수정하지 않습니다.

- 시각 효과 개편 후에도 통합 브라우저에서 전체 곡을 **108 Perfect**로 완주하고 저장했습니다. 그라데이션 노트·실제 히트·카운트다운을 이미지로 확인했으며, 일시정지 상태에서는 캔버스 이미지와 음악 시각이 모두 고정됨을 확인했습니다. CSS 화면 폭 약 300px / 1,024px에서 가로 넘침이 없고 모션 감소 설정에서 장식 애니메이션이 중지되는지도 확인했습니다.

Python 테스트에는 설치된 Starlette의 `httpx` 테스트 클라이언트 사용 중단 예정 경고가 1건 있습니다. 테스트 실패나 의존성 충돌은 없으며, 경고를 숨기지 않습니다. 독립 실행 Chrome·Edge·Firefox·Safari와 실제 오디오 출력 장치별 지연은 검증하지 않았습니다.

## 첫 버전의 제한

- PC 키보드 싱글 플레이, 단타 노트, PCM WAV만 지원합니다.
- 모바일 화면에 맞춰 레이아웃은 조정하지만 터치 플레이는 제공하지 않습니다.
- 롱노트, 회원가입, 공식 랭킹, 멀티플레이, 채보 편집기, 자동 채보 생성은 없습니다.
- 네트워크 오류 후 결과 재시도는 해당 화면이 열려 있는 동안 가능합니다. 저장 전 새로고침하거나 플레이를 종료하면 미저장 결과를 복구하지 않습니다.
- 설정은 브라우저별, 기록은 서버 저장소별로 공유됩니다. 사용자별 기록 분리는 없습니다.
- 실제 기기의 청각적 동기화, 하드웨어 지연, 모든 브라우저의 호환성을 자동 테스트만으로 보장하지 않습니다.
